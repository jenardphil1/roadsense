# Google Maps Reverse-Engineering Report → DPWH Road Distress Detection System

**Prepared:** 2026-10-17 · **Toolchain:** REA (controlled browser replay + passive CDP inspection) with a supplementary raw CDP probe
**Target inspected:** Google Maps Web (https://www.google.com/maps/), desktop + emulated mobile viewport
**Purpose:** Extract transferable UI/UX, interaction, and performance patterns for a Flutter + YOLOv8 road-defect mapping app (Android + Flutter Web, zero-budget).

- **Observed** = directly captured in this session (screenshot/DOM/a11y/network/timing).

- **Assumption** = unverified; flagged as such.

## 1. Executive summary

Eleven controlled browser scenarios against Google Maps Web produced a measured reference for every element your thesis app needs: search bar, floating map controls, results list, error states, and load profile. Key observed results:

- **Cold load** (fresh profile, unthrottled): navigation `load` event in **≈0.82 s**, **118 requests** (59 image, 19 script, 17 XHR), **0 JS page errors**, map DOM only **562 nodes**, JS heap **≈37.5 MB** — heavy rich app stayed light because map rendering is delegated to a canvas/vector renderer, not DOM.
- **Interaction:** drag pan updates map + URL coordinates, produces new tile/network work but **no heap growth** (Δ ≈ −0.6 MB) — rebuild discipline and tiling make panning cheap. Wheel zoom is **fractional/smooth** and preserved in URL.
- **Search:** combobox → 5 suggestions (name + address) → Enter → URL switches to `/maps/search/<q>/@lat,lng,18z` and results render as a **scrollable list panel** plus independent **vector/canvas markers** (no DOM marker images, **no clustering observed** — Google manages density with list pagination + zoom-level labels instead).
- **Slow network** (1.6 Mbps / 650 ms RTT): TTFB **0.68 s**, FCP **3.3 s**, `load` **15.3 s** — Google degrades *progressively* (tiles stream in) rather than blocking on a spinner.
- **Location denied** (no geolocation permission): observed feedback strings: *"Google Maps does not have permission to use your location — Learn more"* and a persistent chip **"Cannot access your location"** — errors surfaced *in the control*, not as modal dialogs.
- **Storage:** Google Maps uses **IndexedDB** (`maps-ml`, `emscripten_filesystem`) and a Service-Worker **Cache Storage namespace `"offline-v1"`** — confirming a cache-offline-render pipeline design (observed; implementation details inferred).
- **Marker design:** category-related POIs use a single consistent shape family — small circle/pin with colored glyph + optional text label; legality attribution always bottom-right; scale bar is a live control reading "1 km"/"50 m".

**Translation to your thesis (sections 6–12):** a `flutter_map`-based single "map-first" screen with a compact search bar, right-edge control stack (my-location, zoom-independent capture FAB), a `flutter_map_supercluster`-clustered five-class categorical marker system (category ≠ severity), a detail bottom sheet (image preview, class, confidence, GPS ±accuracy, timestamp, sync state), viewport-bounded Drift SQL queries, offline capture + idempotent background sync to Supabase/free tier, and on-device TF Lite (Android) with a backend inference path for Flutter Web. No severity classification (Depression/Code 05 excluded class is never surfaced).

### Methodology (repeatable)

1. Edge 155.0.4283.45 (Chromium) launched headless with a seeded profile and CDP on loopback; REA `capture_browser_scenario` in **connect** mode attached to the page target.
2. Scenario A — cold load: `goto https://www.google.com/maps/` (wait until `load`), settle 8 s, capture screenshot + accessibility tree + final URL; record per-step elapsed_ms and network/console/page-error events.
3. Scenario B — search flow: click `[role=combobox][name=q]`, type "quezon city hall", dwell 1.4 s, capture suggestion list, press Enter, dwell 6 s, capture URL/results panel/marker and DOM counts.
4. Scenario C — interaction: 3-wheel zoom at viewport center, 10-step mouse drag (~485 px), re-capture coordinates/URL/heap.
5. Scenario D — my-location denied path: click **Show Your Location** without geolocation permission; capture resulting UI text.
6. Scenario E — throttled load (`Network.emulateNetworkConditions`: 1.6 Mbps down / 750 kbps up / 650 ms latency): navigate, screenshot at 7 s, metrics at ~20 s.
7. Scenario F — mobile layout: `Emulation.setDeviceMetricsOverride` 390×844 DPR 3, Android UA; navigate; capture screenshot + AX headings.
8. REA `inspect_web_page` (5 s passive window) captured storage keys, usage/quota, and cache names.
9. A **raw CDP probe** (Node script, `docs/rea-evidence/`, `cdp_probe.mjs`) collected numeric runtime metrics REA's scenario API doesn't expose: `Performance.getMetrics`, navigation/paint/LCP/long-task entries, request totals by host/type, DOM node counts, `img.mapMarker` counts. This supplements — does not replace — REA's evidence: REA artifacts carry authoritative scenario/a11y/network records with evidence IDs.

## 3. Google Maps UI/UX findings — desktop

Evidence: `01-default-view-1440x900.png` (S1), `05-search-suggestions.png` (S5), `06-search-result.png` (S6), `04-mylocation-feedback.png` (S4), `a11y` artifact in `ev_0797fc6e`.

### 3.1 Screen organization — map owns the screen

- **Map canvas fills the whole window.** All chrome floats *over* it with white pills/cards and shadow; nothing but a 72 px left rail permanently occupies layout space. Observed left rail (desktop): hamburger, **Saved** (bookmark), **Recents** (clock), **Get app** at bottom.
- **Search bar sits top-left** as one continuous pill containing the text combobox (`role=combobox`, name "Search Google Maps", `aria-haspopup=grid`), search action, and a blue Directions diamond chip inside the right end. Typing opens a suggestion card *attached below the pill* (S5) — the map area stays visible behind it; the suggestion panel does not cover the map center.
- **Context card under the search bar** (S1): "Pandi · 31°" **"Light traffic in this area · Typical conditions"** — collapsed, dismissible insights about the *currently viewed area*, not an overlay of the place you flew to.
- **Category chips across the top-center** (S1): Restaurants / Hotels / Things to do / Museums / Transit / Pharmacies + a > overflow affordance. One tap = *filter the visible map content* — instant global filter with zero setup.
- **Floating control stack, bottom-right** (a11y names, observed): **Show Your Location** button; **Zoom out** / **Zoom in** stacked vertically; **Browse Street View images** (Pegman) below; **Layers** + "Show imagery" mini-map chips at bottom-left; imagery-layer thumbnails + collapse chevron bottom-right.
- **Attribution + legal strip, always visible bottom:** "Map data ©2026 Google · Philippines · Terms · Privacy · Send Product Feedback" and a **scale-bar control that is itself a button** ("1 km") — the map's trust/consent duties are permanent, compact, one-line, never a footer.

### 3.2 Suggestion behavior (S5, observé)

- Debounced suggestions while typing; each row: primary (place name, bold) + secondary (street, city, region, grey); left circular pin glyph; ≤ ~6 rows; row height ≈ 64–68 px; keyboard + hover roles preserved (grid/option roles observed via `aria-haspopup=grid`).
- The query pill stays anchored; suggestions appear in a floating card; **map viewport is untouched until a row/Enter is confirmed**.

### 3.3 Search results (S6) — list-first, map-second pattern

- After Enter: URL becomes `/maps/search/quezon+city+hall/@14.6479119,121.0496046,18z` — the **camera is moved by the URL** (shareable state), zoom jumps to 18z.
- Left **results panel ≈ 478 px** (33% of 1440 px) with: results heading "Results ⓘ", **Share**, per-result cards: name / rating+count / category / address / *Open · Closes 5 PM · phone* / **Directions** button each; termination footer "You've reached the end of the list." plus an integrity notice ("You're seeing a limited view of Google Maps — See more", unsigned state).
- A **"Collapse side panel"** chevron tab on the panel edge; panel can be collapsed to give the map ≥ 90% width without discarding the query (URL keeps `/search/<q>/`).
- Chips retained at the results top: **Hours** (filter), **All filters** — already scoped to the search context.
- Bottom-of-panel checkbox: **"Update results when map moves"** — explicit opt-in for re-querying on pan; the default avoids chasing the user around the map.
- **"Search this area"** floating pill appears when the user pans away from result density (S6, top-center) — recovers results after losing them, instead of silently re-firing.

### 3.4 Error / empty / loading states (observed)

- **Location denied** (S4 + text capture): banner *"Google Maps does not have permission to use your location — Learn more"* + persistent disabled chip **"Cannot access your location"** where the location dot would be; the My Location icon drops to a muted cross-out state; no modal journaling of failure, no dead-screen.
- **Progressive loading:** blank white → app shell → map paints progressively (tiles stream in even under throttle, S7/S8) — never a blocking spinner over the entire screen; skeletons for panels appear only for the *pending* region.
- **Empty value states** avoided by context chip cards instead of dashboards (e.g., traffic card says "No delays nearby").

### 3.5 Accessibility & mobile layout (observed text + S9)

- Accessibility tree exposes: `application|Map · Use arrow keys to pan the map · Get details about a p…` (keyboard hint embedded in a11y description), all floating controls as named buttons, region labels for chips.
- Mobile (390×844): **app-promo interstitial** ("Open the Google Maps app?" — *Keep using web* outline / *Continue* filled), full-width search pill "Find a place" with hamburger + avatar, "Your location ✗" chip bottom-right, and a **drag-handle bottom sheet** ("Directions", Drive/Two-wheeler/Walk/Public transport grid). Bottom sheet is the primary surface on mobile; desktop uses the left panel. Same information, re-platformed — selection/presentation change, data does not.

### 3.6 Marker & visual hierarchy (S1/S6, observed)

- POI markers: small white circle/pin with **colored glyph** (orange food, teal park, pink hotel/shopping, grey generic) + optional right-side text label shown at sufficient zoom; street/POI labels rendered by the basemap with luminance-aware halo. No marker clusters observed; density handled by (a) zoom-gated label rendering, (b) number of matching results limited/paginated, (c) category chips scoping what's drawn.

### 3.7 Observed net-behavior during idle map use

When the map sits untouched, network activity is minimal; after pan/zoom, image (tile) requests resume — observed event counts in `metrics-load.json` (interaction window): the session kept issuing tile requests *without* UI hiccups and heap stayed flat (§5).

## 4. Observed interaction & map behavior (facts + inference)

| Interaction | What was observed | Inference for adaptation |
|---|---|---|
| Cold navigation (load) | URL `@14.8865024,120.9663488,14z` — default camera zoom **14 (city scale)**, centered on the device-geolocated town (Pandi, Bulacan ph). | Default to a *relevant* city-scale view: start camera on Philippine city nearest to last capture, not planet-wide blank. |
| Wheel zoom (×3, deltaY −120 each) | URL zoom goes **14 → 14.77** (fractional), center floats ~100 px | Smooth/continuous zoom; desktop apps can implement discrete-but-animated zoom steps; fractional camera is a *feel* pattern, not needed for parity. |
| Mouse-drag pan (~485 px) | New center `14.8898772,120.9586512` in URL within 1.8 s release | URL = camera state = deep-link/share/history. For thesis: update `MapController.center` + a compact "coordinates bar" (and optionally the web URL query) on camera idle. |
| Marker tap (POI, list row) | Selecting a row highlights and centers map marker; panel remains; map keeps fall-behind | For defects: list row tap → `MapController.move(camera center; zoom 17)` + open detail sheet — no dead re-center. |
| Suggestion select | Camera animates to result; URL updates with place slug | Debounce ≥ ~400 ms (see policy in §9); on submit, animate camera; keep text input value (don't clear). |
| Marker density | **No clustering observed**; each result = own marker; bound by list-result limits + category chips + zoom-gated labels | For your data (100s–1000s of defects) you *cannot* rely on Google's huge vendor infra: implement `flutter_map_supercluster` (verified package) at zoom < 15 with count badge, expand on tap to either zoom-in or temporary "reader list" sheet. |
| Search-update semantics | **"Search this area"** pill appears when panned off; "Update results when map moves" opt-in checkbox; both observed | Never silently refresh markers on pan; use idle-pause + explicit "Search this area" (matches offline-capable pipeline + saves queries). |
| URL as state | Every navigation change (search, place, zoom) reflected in URL (`@lat,lng,z`, `/place/…`, `/search/…`) | Web build: sync a minimal `?c=lat,lng,z` + `?focus=id` to the browser history for shareable defect views; Android: ignore. |
| Attribution | Always-on bottom strip; scale bar is a *control* (1 km ↔ 50 m) | Attribution = legal requirement for OSM-derived tiles (§9). Render 1-line bottom-right, never hidden. |
| Empty/edge states | "You've reached the end of the list.", limited-view notice, Keep-using-web interstitial | Build *papers over* unknown-length datasets by declaring the end early rather than infinite-scrolling surprises. |

**Not observed / out of scope:** marker clustering behavior of gmaps (does not exist for POIs), routing UX internals, 3D/globe mode, native app.

## 6. Proposed UI for the DPWH Road Distress Detection System

Principles lifted from observations: **map occupies > 85% of pixels**; **one compact top-left search**; **right-edge control stack**; **left/bottom surface for lists + detail**, collapsible; **errors live in the controls**, not modals; **URL = camera state** (web); **attribution permanent**.

### 6.1 Screen map (mobile ≤ 600 dp width, web/desktop ≥ 900 dp)

```
┌────────────────────────────────────────────────────────────────────────┐
│ [☰] Search… roads/defects/filter  [🔍 | Directions→Analytics 📊]  (top-left, 44px) │ ← search bar (srch)
├───────────────────────────────────────────────────────────────┬────────┤
│                                                                │ Left   │
│                    FLUTTER MAP (OpenStreetMap raster)          │ Panel  │
│                    markers = clustered 5-class icons           │ (web ≥ │
│                                                                │ 900dp) │
│   ⤺(FAB capture 📷) ──── above ⌖(my-location) ➕ / ➖ (zoom)     │ [List/ │
│                                                                │ Detail]│
│  ▸ Collapsed: Defect-detail / Capture / Filters (bottom sheet)  └────────┘
│                             Legend (chips, collapses to "5 classes")     │
│  ↳ offline-sync status banner (claimed chip when online/pending/bad)     │
│  © OpenStreetMap contributors · scale (button toggles km/mi) · DPWH chip │
└────────────────────────────────────────────────────────────────────────┘
```

Mobile: right-edge stack = **Capture FAB (primary, teal, 56dp)** → my-location (Med button, 40dp) → zoom optional (hidden until map has focus, since pinch is primary). Bottom sheet for: search results list, **defect detail**, **capture confirm**, **filters**.
Web/desktop: left panel replaces current bottom sheet overlay; the map keeps ≥ 60% width; panel collapses to a 20px edge-tab (observed gmaps "Collapse side panel" affordance).

### 6.2 Screen components (one paragraph each)

1. **Compact search bar** — 44dp pill; routes to three search modes: (a) *Defects nearby* — searches captured records by road/note text (local Drift LIKE/prefix, instant); (b) *Place search* — geocoding (see §9; submit-triggered due to Nominatim policy; Photon suggestions optional and rate-managed); (c) *Filters apply*. Camera centers on chosen result, zoom ≤ 17.
2. **Full-screen interactive map** — `flutter_map` + MapController; light DOM; tiles stream progressively; attribution strip bottom-right; scale-bar chip. **Full map stays first**: no peripheral panel can cover more than 45% width on web, 55% height on mobile.
3. **Current-location button** — permission-aware states (see §6.4): ready (blue target icon), denied (muted + red dot + a Learn-more chip like gmaps' "Cannot access your location"), searching (pulsing ring). Tap centers once; long-press toggles follow mode.
4. **Category markers (5 classes)** — §7 design below; nothing draws at zoom < 13 except clusters; ≥ 13 draws clusters and category markers with count; zoom ≥ 16 shows individual markers at 30–34dp plus optional tiny label with road name only for top-confidence single record of that spot.
5. **Marker clustering** — `flutter_map_supercluster` w/ `clusterData` count badge; tap = **zoom to subdivision, degrees range 0.005**. At > 5,000 records, cap display to records within current viewport + zoom (§10).
6. **Legend** — bottom-left chips (like gmaps' Layers chip): colors + names per class + counts, collapsible into a hint pill. Not severity! categories only.
7. **Defect-detail bottom sheet** — image preview (first, cached), class name + confidence (e.g. "Alligator crack · 87%"), capture date/time, GPS lat/lng + **±X m accuracy** (own chip, styled separately from confidence!), source (synced/pending), user note, actions (retake/delete/locate). Includes mini-map preview of the location.
8. **Image preview** — 96dp rounded; loaded via `Image.file`+ LRU memory cache; *full* image on tap; never decoded in the marker itself.
9. **Confidence** — model confidence displayed as a **classification-strength meter**, max 5 bars; label "Model confidence" explicitly; never shown alongside GPS accuracy as if comparable.
10. **Capture date/time** — relative ("2 h ago") + absolute on tap.
11. **GPS accuracy chip** — text like "±6 m" green (≤ 8 m) / amber (9–20 m) / red (> 20 m, with "Move for better signal" tip); shown during capture and in the detail sheet.
12. **Filters (defect class + date + source)** — chips + sheet: 5 class toggles with counts in legend colors; date presets (24 h / 7 d / 30 d / all) instead of 2 date pickers on mobile; "Pending sync" toggle; every toggle updates markers without redrawing the map layer (§10 rebuild strategy).
13. **Capture action (FAB)** — opens camera; on capture, runs TF Lite inference (isolate) on Android or posts to backend (Web); shows only the load line "Checking for road damage…" ≤ 2.5 s typical; then review sheet: preview, detected classes + confidences (multi-detection possible — one image may yield several chips); confirm → writes record locally + syncs.
14. **Offline status + sync feedback** — status chip top-of-map ("N changes pending · will sync" / "Syncing…" / "Offline — saved on device"); tapping opens pending list; **no blocking of capture when offline** (records queue locally with UUID idempotency keys).
15. **Dashboard entry** — located inside the left rail (Saved-like slot: "Dashboard") on desktop, and in the search-bar trailing chip (analytics icon) on mobile → separate page, never an overlay on the map (keeps map-owned-screen principle). Content: counts per class, trend by day, accuracy distribution, sync health, roads coverage heatmap link.

### 6.3 Flow: capture a defect while walking/riding

```
Tap 📷 FAB → camera preview ("target chest aligned to road") → Capture →
  GPS chip shows ±[15] m (amber) — user can "Hold for 2 s more" to improve if > 8 m
  (geolocator single-shot at high accuracy; do not poll continuously)
→ Inference (tflite isolate) ≤ 2.5 s → review sheet lists every detection
  [Pothole 90% ✓] [Alligator crack 62% ✓] with image thumbnail
→ Confirm → record(s) saved locally (SQLite, incl. per-detection GPS accuracy metric ±m)
→ chip: "1 saved · will sync" — capture-ready again in < 1 s.
```

The *GPS uncertainty and the model confidence are separate* fields end-to-end (col names: `accuracy_m`, `confidence`); UI labels never mix them.

### 6.4 Permission / location robustness (mirrors observed gmaps behavior)

| Case | UI state | Behavior |
|---|---|---|
| Permission granted, good fix | Blue target icon; "±6 m" chip on capture | One-shot `geolocator.getCurrentPosition(LocationAccuracy.high)`; `timeLimit` 15 s. |
| Permission denied | Icon → muted; red but non-blocking chip "Location unavailable — allow access to attach coordinates" (tap = open settings `UrlLauncher`/app settings on Android) | Capture still allowed; record saved with `gps_pending=true`. |
| Service off / GPS drift > 20 m | Chip red "±32 m — weak signal"; suggestion text | Use `accuracy_m` derived from `Position.accuracy`; show at capture + detail; also store `timestamp`. |
| Follow-my-location disabled | auto after user pans | Do **not** fight user input; re-enable only on my-location tap. |

## 7. Five-class marker design (category ≠ severity)

**Requirement:** confusion-free, accessible, *type-based*, not severity-based; label fidelity must match the trained model's exported class mapping. Verified mapping to carry into code (order taken from your config):

| Export id | DPWH Code | Label in app | Glyph (shape distinct, not color-only) | Base color (Okabe-Ito) | Legend label |
|---|---|---|---|---|---|
| 0 | 01 | Pothole | filled irregular blob with jagged inner outline | **Vermillion #D55E00** | "Pothole" |
| 1 | 02 | Alligator crack | closed cell-grid (3×3 mesh) outline | **Sky blue #56B4E9** | "Alligator crack" |
| 2 | 12 | Longitudinal crack | vertical dashed line | **Bluish green #009E73** | "Longitudinal crack" |
| 3 | 12 | Transverse crack | horizontal dashed line | **Straw-yellow #F0E442** (dark 1.5px border for map contrast) | "Transverse crack" |
| 4 | 01 | Edge break | corner tile notch (quarter-circle cut) | **Reddish purple #CC79A7** | "Edge break" |

Rules:
- All markers same size (30 dp circle, 1.5 dp white border), same tap target radius; glyph is a **CustomPainter** (three vertices variance, painted once per class then cached) — no per-marker image decode.
- Color is *supported*, never *sole*: shapes differ; a text label appears in the legend, in the detail sheet, and as a tooltip when zoom ≥ 16 (legend + tooltips observed in gmaps' a11y pattern).
- Excluded class **Depression (Code 05)**: never offered by filters/legend; unlabeled code is not surfaced in UI; internal schema keeps `classId` numeric so re-training inclusion is a config change, not a UI migration.
- Cluster marker: single circle, count; color = neutral navy (never one of the class colors) to avoid implying any category; expands on tap.
- Confidence ring optional at zoom ≥ 16: subtle 270° arc = model confidence — separate visual band from class color and it is drawn *only on individual markers*, never clusters.

## 8. Recommended Flutter mapping architecture

**Layering rule — never couple any two of these:**

```
[UI/Flutter]  →  [MapView (flutter_map)]   →  [TileProvider (pluggable URL)]
        ↓                                          ↑
[Detections Controller (Riverpod)] → [Drift DB (SQLite/JS-WASM)] ←→ [Sync Service]
        ↓                                          ↑
[Inference Service (Android: tflite_flutter isolate  |  Web: HTTP backend)]
                                                   [Geocoder proxy (server)]
```

| Concern | Component | Package / service | Platform | Cost |
|---|---|---|---|---|
| Map renderer | `flutter_map` **8.x** (verified current 8.3.2, publisher fleaflet.dev) | pure Flutter, works Android + Web | free |
| Clustering | `flutter_map_supercluster` **4.3.0** (verified active; efficient add/remove) | Android + Web | free |
| Basemap tiles | `TileLayer(urlTemplate: …)` — provider is *config*, §9 | any | free |
| Tile caching | HTTP-header-respecting cache (respect provider policy; §9) | Android + Web | free |
| Place lookup | **Photon** (suggest/suggestions) + **Nominatim** (submit/fetch) via your server proxy — not client-direct | all | free |
| Geocoding client | Dart `http` + JSON models (no heavyweight SDK) | all | free |
| GPS | `geolocator` (`getCurrentPosition`, `Position.accuracy`) | Android + Web | free |
| ML on-device | `tflite_flutter` **0.12.1** (official TF-org publisher; *described as mobile & desktop; no web*) | **Android only** | free |
| ML on Web | self-hosted inference endpoint (FastAPI + ultralytics YOLOv8) on the same free backend as sync | web | free tier |
| Local DB | **Drift** (SQLite; Web via sqlite3 WASM) with spatial index query helper | Android + Web | free |
| Backend | Supabase free tier (Postgres + RLS + file storage) or self-hosted FastAPI + Postgres/SQLite | all | free tier |
| State | `flutter_riverpod` (2.x) with `select`/`family` granularity | all | free |
| Sync | `workmanager` (Android periodic) + `connectivity_plus` listener; idempotency key = record UUID | Android; web = on-load flush | free |

**Anti-lock-in decisions (the "no hard-coded URL" rule is a *recommendation* of OSMF's own tile policy):**
- Tile URL template, geocoder base URL, and backend base URL live in one `config.dart`/`AppConfig` file with a runtime switcher (debug drawer swaps provider without app update) — matching OSMF's "avoid hard-coding the tile URL" and Nominatim's "apps must be able to switch service at our request" requirement.
- Schema is backend-agnostic: one `Detections` table in Drift with `remote_id` nullable; sync = upsert-by-uuid; delete = tombstone.
- Inference output schema identical across Android/TF and Web/HTTP paths: `{classId, confidence, bbox, imageRef, capturedAt, lat, lng, accuracyM}`.

### 9.3 AI inference (YOLOv8 → TFLite)

- **Android (primary):** export after training: best.pt → **TFLite (FP16 or INT8)** → bundle model file in `assets/` → `tflite_flutter` (`TensorFlowLite.loadFromAsset('dpwh_model.tflite')`), run inside `Isolate.run` / background messenger so the map thread never janks.
- **Web:** `tflite_flutter` does **not** support Flutter Web (publisher description limits to *mobile and desktop*). Practical zero-cost choices:
  - **Option A (recommended for thesis):** same library-free approach inside the app for Android; for Web **post the captured image to your backend** where a tiny FastAPI service loads `yolov8*.onnx`/`.pt` (ultralytics) and returns the identical detection JSON. Cold-start cost is real (free instances sleep) — show a "Model starting" state.
  - Option B: burn-type TensorFlow.js via `dart:js_interop` (custom bridge; higher work, still free; TFJS runs YOLOv8n acceptably on desktop browsers).
  - Option C: run YOLO on web only for *subtitles* (i.e., inference on backend always). — same as A but no Android model: **not recommended** (offline capture breaks).
- The DPWH class mapping must be **read from the exported model's `metadata`** (e.g., `saved_model.pb`-adjacent `.yaml` or a Dart-embedded constant list you verify at build time with a unit test comparing label order to the exported config) — per your constraint that dataset class IDs may not match deployed model IDs.

## 15. Risks, trade-offs, and things explicitly *not* worth building

1. **Zero-budget means no offline basemap promise** — OSMF's own policy forbids bulk tile prefetch. Accept online basemap; offline capability = *your records + images*, which actually defends the thesis claim (offline collection of defects).
2. **Flutter Web inference**: no native TFLite; either a) accept online-only capture on web, b) keep a live backend model, or c) TFJS bridge (high effort). Recommend (a)+(b): web = reviewing/monitoring tool; Android = field tool. State this clearly in the thesis scope.
3. **Supabase free tier pause** — projects pause after ~1 week of inactivity; ping before demo; or prefer self-hosted FastAPI+SQLite on a heavyweight machine at the faculty.
4. **Nominatim autocomplete ban** — you *cannot* legally build Google-style instant suggestions on public Nominatim; Photon gives you them free but without SLA. Put both behind your backend proxy (switchable per OSMF/Nominatim requirement) — never call from device directly.
5. **Marker legibility on older Androids** — CustomPainter > image assets > SVG-rendered widget; keep < 3 ms paint budget; don't put `FadeInImage` in a cluster icon.
6. **Legal hygiene** — never copy Google assets/icons; your UI is a *pattern* reference only; add your own icon set (Material Symbols is safe and free), your own name/branding, correct attribution strings.
7. **Model discipline** — labels must match exported mapping (test T4 asserts class ∈ {0..4}); Depression (Code 05) is excluded by config and never appears in UI filters or legends; no severity scale exists in the model — confidence ≠ severity ≠ accuracy; keep all three orthogonal in schema (`confidence`, `accuracy_m`, and `class` only).
