## Fixed

- **Web Google initialization:** the native GoogleSignIn helper is lazy and is neither constructed nor signed out on web. Firebase web popup/redirect authentication remains the web implementation.
- **Remember me:** web password and Google sign-in now select local or session persistence. Password whitespace is preserved instead of silently trimmed.
- **Verification routing:** both entry points use a shared verification gate. The form remains mounted during registration, and an unverified new account stays in the verification flow instead of opening the map immediately.
- **Responsive auth:** header, telemetry badge and remember/reset controls adapt to enlarged text; Google-button text and footer text can shrink/wrap within their columns. Tests cover 200% text on phone and desktop.
- **Onboarding:** feature and permission card titles flex beside badges, fixing small-phone overflow.
- **Accessibility:** muted text and dark web links have stronger contrast, password visibility controls have labels, auth tabs use keyboard-operable InkWell controls, and repeating auth/onboarding animation honors reduced-motion settings. This is not a full WCAG certification or TalkBack/VoiceOver review.
- **Website metadata:** replaced Flutter placeholder description and Apple app title.
- **Web location:** removed an unsupported `getLastKnownPosition` call that prevented the subsequent browser location request. Map-coordinate URL reloads now start at the root Flutter route without the initial-route warning.
- **Report creation rules:** accepted fields now match the DPWH/LGU metadata the app actually sends. Empty image URLs remain supported for manual reports; supplied image URLs still require the trusted Azure location.
- **Report editing rules:** owners can edit valid pending reports; approved reports remain protected. Owner edit controls are disabled for approved reports in both profile UIs. Coordinate, count and severity validation was added to the service.
- **Trash rules:** an owner cannot delete an approved report merely because an administrator put it in trash. Empty-trash logic only selects that owner's eligible deleted reports. Admin creation of the system-settings document is allowed.
- **Mobile report reliability:** failed uploads no longer clear the capture and claim cloud submission. A per-account outbox persists the image and report before upload, retains failures across restarts, retries while the app is open and at next startup, and uses stable report/blob IDs to avoid duplicate submissions after retries. Queue ownership and concurrent retry behavior are tested.
- **GPS integrity:** report submission stops when GPS is unavailable instead of using a fabricated fallback coordinate.
- **Image format:** annotated PNG uploads retain PNG extension/content type rather than being mislabeled JPEG.
- **Mobile lifecycle:** repeated report listeners are cancelled/replaced, and timers/listeners stop when the home screen is disposed.
- **Generated database code:** generated the missing Drift part so the unused database module no longer produces analyzer errors. Regenerate it with `dart run build_runner build --build-filter=lib/database/app_database.g.dart` after schema changes.

Web and mobile keep their separate entry points, map screens and profile screens. Shared authentication/data changes apply intentionally to both. Pre-existing workspace edits were preserved.

Setup from the repository root:

```powershell
npm.cmd install --prefix .dart_tool/qa-browser playwright firebase-tools firebase firebase-admin --no-audit --no-fund
node .dart_tool/qa-browser/node_modules/firebase-tools/lib/bin/firebase.js emulators:start --only auth,firestore --project demo-roadsense-qa --config firebase.qa.json
```

In another terminal, `node test/firebase_workflows.cjs` creates local accounts and checks the backend. `node test/seed_qa_reports.cjs` seeds the browser fixture reports. Build the local web target with `flutter build web --debug --no-pub -t lib/web_main.dart --dart-define=FIREBASE_EMULATOR_HOST=127.0.0.1 --output build/qa-web`, serve `build/qa-web` on port 8081, and run `node test/browser_workflows.cjs`. Use **localhost** for this debug emulator browser test: this FlutterFire version restores the emulator connection early only on that hostname in debug mode. The browser test refuses to enter account credentials unless the emulator warning is present.

`flutter test --no-pub` runs the unit/widget suite. UI tests currently load Windows Arial from `C:/Windows/Fonts/arial.ttf`, so they approximate native font metrics and require that font path.

The Android integration test is `integration_test/mobile_workflows_test.dart`. Run it with a device ID, emulator host and local QA account supplied through `QA_USER_EMAIL`/`QA_USER_PASSWORD` dart-defines. The created AVD lives in ignored `.dart_tool/android-avd`; Android emulator/system-image packages were installed in the existing SDK. Debug-only cleartext HTTP supports local Firebase; release defaults remain unchanged. Grant camera/location permissions and inject the documented coordinate through the emulator. These are test fixtures, not production credential settings.

For release verification, omit emulator flags: `flutter build web --no-pub -t lib/web_main.dart` and `flutter build apk --debug --no-pub -t lib/main.dart`. Required platform check: `flutter analyze lib/web_main.dart lib/web_map_screen.dart lib/web_profile_screen.dart --no-pub`.

Firebase documents [local Auth emulation](https://firebase.google.com/docs/emulator-suite/connect_auth) and [web session persistence](https://firebase.google.com/docs/auth/web/auth-state-persistence). Local action-link testing does not establish live mailbox delivery.
