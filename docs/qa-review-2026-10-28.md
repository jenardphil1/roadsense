## Findings

1. **Medium — onboarding overflow on small phones.** `lib/onboarding_screen.dart:1522` places a title and badge in an unconstrained horizontal row. The 375px widget run reports approximately 9.7px and 0.12px right overflows. Reproduce with `flutter test test/ui_audit_test.dart --plain-name "onboarding layout and completion at width 375.0"`. Allow title flex/wrapping or wrap the badge below it. The failing test is retained as evidence, not suppressed.
2. **Medium — Remember me has no functional connection.** In `lib/auth_screen.dart`, `_rememberMe` is only initialized, displayed, and toggled (lines 26, 2397–2407). Neither sign-in submission nor `CloudService.signIn` consumes it or selects persistence. Session behavior therefore does not change with this checkbox. Verified by source tracing, not a live session experiment.
3. **Medium — insufficient text contrast in shared design tokens.** Computed sRGB ratios: muted light text `#94A3B8` on white = 2.56:1; muted dark text `#64748B` on `#0F172A` = 3.75:1. Both fall below 4.5:1 for ordinary text. The web brand-on-surface token `#2563EB` on the dark surface is 3.45:1, unsuitable for ordinary-sized link text. These are token-pair measurements, not a complete rendered-page accessibility audit; exact usage and backgrounds must be checked when fixing.
4. **Medium — password controls lack accessible names; keyboard coverage incomplete.** The browser accessibility tree exposes the password visibility control as an unnamed button (around `lib/auth_screen.dart:2350`). Contrary to the initial source-only concern, Flutter does expose the custom Sign In/Register controls as buttons. Full keyboard-only mode switching and selected-state announcements still need verification.
5. **Low — reduced-motion handling needs review.** Auth radar repeats continuously and hazard-marker animation has no local reduced-motion check. This is a source-review concern; OS reduced-motion behavior was not exercised.
6. **Low — website metadata remains template content.** `web/index.html` has description `A new Flutter project.` and Apple web-app title `my_flutter_app`.
7. **High — web Google sign-in plugin initializes with incompatible configuration.** `CloudService` eagerly constructs `GoogleSignIn(serverClientId: ...)` (`lib/cloud_service.dart:53`). The installed web plugin requires `clientId` or a `google-signin-client_id` meta tag, neither is provided; it also rejects `serverClientId` on web. Debug browser stack reaches `GoogleSignInPlugin.initWithParams` and the compiled assertion says `ClientID not set`. Release also reports an unhandled startup error in the same initialization path. Public login still renders and its local interactions work; Firebase popup login itself was not attempted, so this is not evidence that every Google login path fails. Prefer initializing the native-only helper lazily when the native branch needs it, or supplying valid platform-specific configuration.
8. **Medium — 200% text causes auth overflows on both screen classes.** Reproduce with `flutter test test/ui_audit_test.dart --name "200 percent"`. Phone overflows reach 146px at the header (`auth_screen.dart:1895`), 46px at Google button (`2244`), 126px at remember/reset row (`2391`), and 109px at footer (`2613`). Desktop has 65px telemetry (`1559`) and 8.7px header overflow. Evidence is in `qa-large-text.log`. These are widget tests with Arial test fonts, not exact on-device screenshots.
